## How to run

Two steps. Do not skip the first — the R scripts read files that only exist
after it runs.

### 1. Data preparation (Python, needs Spark)

```bash
cd chapters/03-manuscript-figures/figure_1
uv run jupyter nbconvert --to notebook --execute --inplace figure_1_dataprep-r1.ipynb
```

Writes everything into `data/`. Requires the local Open Targets 25.06 release
under `data/25.06/` and the intermediate files from Chapter 01 / the R1 analysis
notebook (see _Inputs_ below). Takes a few minutes and about 40 GB of driver
memory.

### 2. Render the figure (R)

```bash
cd chapters/03-manuscript-figures     # NOT figure_1 — see below
Rscript figure_1/Figure_1_combined.R
```

Output: `figure_1/Figure_1_combined-r1.pdf`, 15.00 × 11.48 in, one page.

`Figure_1_combined.R` is the only script you run. It sources the other three
itself.

## Environment gotchas

These cost real time to rediscover.

- **Run R from `chapters/03-manuscript-figures/`, not from `figure_1/`.** The
  renv project root is the chapter directory — that is where `.Rprofile` and
  `renv.lock` live. Running `Rscript Figure_1_combined.R` from inside
  `figure_1/` activates no library and dies with
  `there is no package called 'circlize'`. The scripts resolve their own
  directory from the `--file=` argument, so passing
  `figure_1/Figure_1_combined.R` works fine.
- **`renv::restore()` fails on `arrow`** with
  `libtool found appears not to be Apple's libtool: /usr/bin/libtool` —
  Homebrew's GNU libtool shadows Apple's during the Arrow C++ build. Use a
  prebuilt libarrow instead:
  ```bash
  cd chapters/03-manuscript-figures
  LIBARROW_BINARY=true NOT_CRAN=true Rscript -e 'renv::restore(prompt = FALSE)'
  ```
  `arrow` sorts first alphabetically, so this failure aborts the whole restore
  and leaves _nothing_ installed — the error looks worse than it is.
- **`pdftools` is not in `renv.lock`** but `Figure_1_combined.R` needs it
  (`pdftools::pdf_pagesize`, to derive panel a's height from its aspect ratio).
  Install separately; it needs `poppler-cpp` (`brew install poppler`):
  ```bash
  Rscript -e 'renv::install("pdftools", prompt = FALSE)'
  ```
- **macOS only.** `Figure_1_combined.R` uses `quartz(type = "pdf", ...)` and
  shells out to `sips` to rasterise panel a. Neither exists on Linux, despite
  the repo README claiming Ubuntu support.

## Changes for reviewer round 1

The reviewer objected that the ancestry split was binary — `EUR` = predominant
ancestry ≥90% non-Finnish European, `non-EUR` = _everything else_ — so an
89%-European pan-ancestry meta-analysis and FinnGen both counted as "non-EUR". A
third class, `mixed` (no single ancestry reaches 90%), now separates them. Full
reclassification and numbers: `chapters/06-review-r1/ancestry-mixed-split/`.

Only panel c and the panel d donut changed. Panels a, b and the circular
Manhattan are re-rendered unmodified.

published input file:

| ------------------------------- | ------------- |
| published `str_split` on commas | **38,206**    |
| correct (proper list explode)   | **35,535**    |

The genes panel was never affected. Reading pre-computed layers removes the
whole failure mode and guarantees panel c, ED Fig. 3 and the reviewer response

Panel d's parquet is rebuilt following the join the old notebook used:

```python
disease_ta_measur       = disease_ta.join(measur, on="geneId", how="outer")
disease_ta_measur_index = disease_ta_measur.join(target_index, on="geneId", how="inner")
```

`measur` (unique measurement traits per gene) was the only missing ingredient
and is recomputed from the R1 measurement table. It feeds a circos track that is
commented out in `Figure_1_d.R`, and measurement-only genes entering through the
outer join carry NA on both plotted tracks, so this cannot change the rendered
panel. The rebuild yields 15,641 rows, matching the "Total unique genes across
both: 15641" printed by the original analysis notebook.

One provenance caveat on panel b: the published version was built from a `25.07`
`lead_variant_effect` snapshot read straight from GCS, using
`abs(rescaledStatistics.estimatedBeta)`. The local 25.06-derived table has no
`estimatedBeta` field — `rescaledStatistics` exposes `absEstimatedBeta` — so
that is used instead, keeping the output column name the R script reads. Panel
b's lines may differ marginally from the published figure.

## Known issues, deliberately left alone

- `Figure_1_combined.R` sources its siblings by `readLines()`, grepping for
  `^ggsave\(` or `^main\(\)$`, deleting those lines and `eval(parse(...))`-ing
  the rest. Reformatting a sourced script silently breaks the parent.
- The "fully vector PDF" comment at the top of `Figure_1_combined.R` is wrong:
  panel a is rasterised to 3000 px via `sips` and re-embedded.
- Panel geometry requires `left_w == 0.3 * total_w` to be maintained by hand.
- `Figure_1_d.R` prints ~80 lines of per-chromosome debug output and a
  meaningless "WARNING: Overlapping regions between _n_ and _m_" loop (it
  compares coordinate ranges _across_ chromosomes) on every render. It also
  carries ~150 lines of commented-out track code, and its
  `cat("Found", n, "genes with uniqueDiseases > 50\n")` message states 50 while
  the filter uses 35.
- `Figure_1_facet.png`, `circular_manhattan_plot_no_logo.png` and
  `l2g_diseases_full.csv` are committed intermediates that nothing in the
  current pipeline reads.
